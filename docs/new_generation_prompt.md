# NEW GENERATION PROMPT (Hierarchical Support)

## STRUCTURE

Respond ONLY with valid JSON, no other text. Generate ONE numbered QUESTION block, which may contain:
- **Flat structure:** Multiple independent sub-questions (1.1, 1.2, 1.3...) at depth 0
- **Hierarchical structure:** A stem row (1.5) with no marks, introducing nested children (1.5.1, 1.5.2...) at depth 1
- **Mixed:** Combine both (1.1, 1.2, 1.5 stem, 1.5.1, 1.5.2, 1.6) -- any arrangement

Do NOT generate numbering strings (no "1.1", "1.5.1"). Numbering is generated by Python from depth and position.

Return structure (one object):
```json
{
  "question_structure": [
    {
      "type": "stem_row",          // or "flat_row"
      "is_stem": true,             // false for flat/children
      "parts": [{"type": "text"|"math", "value": str}],
      "marks": null,               // stems ALWAYS have marks: null
      "cognitive_level": null,     // stems ALWAYS have cognitive_level: null
      // If stem, optional "children" (see below)
      "children": [...]            // ONLY for stems; depth-1 rows
    },
    {
      "type": "flat_row",
      "is_stem": false,
      "parts": [...],              // question text
      "marks": 2,                  // flat rows have marks > 0
      "cognitive_level": "routine",
      "answer": [...],             // final answer (parts format)
      "marking_steps": [...]       // marking guide steps
      "problem_type": "equation|inequality|system|unverifiable",
      "sympy_problem": "...",
      "claimed_solution": "[...]"
    }
  ],
  "total_marks": 6  // Sum of all leaf marks (stems contribute 0)
}
```

CHILD STRUCTURE (inside stem's "children" array):
```json
{
  "parts": [...],                  // sub-question text
  "marks": 3,                      // child ALWAYS has marks > 0
  "cognitive_level": "complex",    // child ALWAYS has cognitive_level
  "answer": [...],                 // final answer
  "marking_steps": [...]
  "problem_type": "...",
  "sympy_problem": "...",
  "claimed_solution": "..."
}
```

KEY RULES:
1. NUMBERING: Do not include number strings. Return only structure (type, is_stem, marks, level).
2. STEM RULES: is_stem=true means marks=null and cognitive_level=null. Stems MUST have ≥2 children.
3. FLAT RULES: is_stem=false means marks>0 and cognitive_level is set.
4. CHILDREN: Nested under stem's "children" array. Each is complete (question, answer, marking_steps, etc.)
5. PARTS FORMAT: All question/answer/marking_steps use parts list: [{"type": "text"|"math", "value": str}]
6. MATH NOTATION: Same as before -- DSL only (^{}, _{}, \frac, \sqrt, unicode symbols typed directly)
7. DECIMALS: South African comma notation (3,25 not 3.25). Thousands: space (R500 000, not R500,000)
8. COGNITIVE LEVEL TARGETS: You will be given a target distribution per question, e.g., {routine: 4 marks, complex: 2 marks}. Allocate your leaves' cognitive_level to match these targets.
9. MARKS TOTAL: All leaf marks must sum to the total_marks passed in the context (e.g., 6 for a 6-mark question).
